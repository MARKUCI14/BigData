# Course deliverables and evidence

This checklist maps the 2026–2027 Big Data semester project brief to the team's project artifacts. Update evidence links as implementation and presentations are produced.

| Deliverable / review | Brief asks for | Project evidence and status |
| --- | --- | --- |
| Proposal (weeks 3–4) | Title, problem statement, motivation/impact, sources, preliminary architecture, team/roles | Accepted proposal supplied by team. Keep a copy/reference in course submission materials. |
| Architecture review (weeks 5–6) | Refined architecture, technology justification, implementation plan, risks/mitigations | `../architecture/overview.md`, the ADRs in `../architecture/`, `../technical-decisions.md`, and a project plan/risk register to add. |
| Progress demonstration (weeks 11–12) | Implemented pipeline components, functionality, preliminary analytics, progress | Add a progress note/demo checklist with working commands and outputs when available. |
| Final submission (weeks 13–14) | Technical report, source repository, architecture docs, deployment/execution instructions, slides | `docs/` and repository; add report, slides, and runnable setup/runbook artifacts. |
| Final demonstration | End-to-end functionality, batch workflow, stream workflow, analytics and visualizations | Capture a verified demo path for each workflow and ensure every team member can explain it. |

## Requirements from the brief to track

- At least two heterogeneous data sources, including one real or realistically simulated streaming source.
- Ingestion, batch storage, speed storage, batch processing, real-time processing, and serving/visualization layers.
- Meaningful analytics (descriptive analytics, aggregation/reporting, trends, anomaly detection, forecasting, recommendations, or monitoring).
- Scalability considerations, coherent integration, reproducibility, and deployment/execution documentation.
- Machine learning, containers, cloud, monitoring, CI/CD, and infrastructure as code are optional enhancements, not baseline requirements.

## Additional project documents to add as work progresses

- Architecture review implementation plan and risk/mitigation register.
- Data dictionary and source/provenance notes.
- Team responsibility matrix and meeting/progress notes if useful for coordination.
- Runbook and demo checklist.
- Technical report and presentation materials.
- AI-use acknowledgment consistent with course submission requirements.
